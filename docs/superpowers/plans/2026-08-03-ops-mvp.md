# OPS MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun modul `/v2/ops` mobile-first untuk katalog, keranjang, pengajuan, CRUD barang, approval, riwayat stok, dan akses dengan data bersama ATK yang dipisahkan oleh `module`.

**Architecture:** Model dan tabel ATK existing tetap menjadi mesin data bersama. Controller dan view OPS dibuat terpisah serta selalu memakai scope `module = OPS`; controller ATK diperketat ke `module = ATK` agar kedua modul tidak bocor. Layout ATK dipakai ulang melalui mode OPS berwarna hijau, sedangkan perubahan schema produksi diberikan hanya sebagai SQL MySQL manual.

**Tech Stack:** Laravel 12, PHP 8.2, Blade, Pest PHP, MySQL 8.4, session cart.

## Global Constraints

- Jangan membuat atau menjalankan Laravel migration.
- Jangan menjalankan SQL terhadap database pengguna; hanya buat file SQL manual.
- Jangan mengubah tampilan atau daftar menu ATK.
- Semua query OPS wajib memakai `module = OPS`.
- Semua query ATK yang memakai tabel bersama wajib memakai `module = ATK`.
- `ADMIN ATK` otomatis memiliki seluruh akses OPS.
- UI OPS memakai bahasa Indonesia sederhana dan mobile-first.
- Delete barang adalah soft delete dengan alasan wajib, pelaku, dan waktu.
- Stok tidak boleh negatif dan perubahan stok harus berada dalam transaksi.

public function canAccessOps(): bool
{

        || $this->hasAccessRole(UserRole::OPS->value)

{
